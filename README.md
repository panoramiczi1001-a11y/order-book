# Order Book（限价订单簿）

从零写一个限价订单簿：下单、撤单、撮合、行情快照。

这不是一个从零开始的项目——`v0/` 是我 2026 年 9 月参加一家量化私募的笔试题答卷。
当时的评语是「这里都是问题」。这份仓库就是我逐条把它们改掉的过程。

**为什么要公开这段不体面的起点**：一个订单簿的骨架谁都能写出来，
难的是知道它错在哪、以及为什么这么改。所以 `v0/` 一个字不改地留着。

## v0 的问题清单

### 一、会算错的

- [ ] `std::min` 用了 `<algorithm>` 却没 include，靠其他头文件间接引入，换工具链即崩
- [ ] 价格用 `double` 作为 `std::map` 的键——浮点相等会静默丢单，应改用整数 tick
- [ ] 同一份订单存了三份（`orderMap` 一份 + 买卖两个 `deque` 各一份拷贝），靠手写 `insert_or_assign` 同步，任何一条路径漏同步就状态分裂
- [ ] `cancelOrder` 里用 `buyOrders[price]`，键不存在时会凭空创建一个空档位
- [ ] 撮合后没有成交记录（trade）输出，无法核对成交价与成交量
- [ ] 撮合循环持有 `deque` 元素引用，中途又 `pop_front`，靠语句顺序侥幸未触发悬垂引用

### 二、结构上不够快的

- [ ] 档位聚合量每次全量重算，应增量维护
- [ ] 撤单 O(n) 线性扫描，应持有节点句柄做到 O(1)
- [ ] `Order` 携带 `std::string` 被多次拷贝，应 move 或改为按 ID 索引
- [ ] `count` + `insert` 两次哈希查找，应改用 `insert` 的返回值
- [ ] `OrderBook` 只有一个买卖簿，`symbol` 字段形同虚设，多标的会串账

### 三、工程规范

- [ ] 构造函数用赋值而非初始化列表
- [ ] `remainingQuantity()` 与 `getRemaining()` 重复
- [ ] `using namespace std;` 放在文件作用域
- [ ] 校验失败时静默 return，事后无法诊断原因
- [ ] 测试只覆盖「一买一卖、整数价格、50 轮」，**`cancelOrder` 从未被调用过一次**

## 修复路线

- [ ] 1. 价格改为整数 tick；三份数据收成一份（`orderMap` 持有节点句柄）
- [ ] 2. 撤单 O(1)
- [ ] 3. 档位总量增量维护
- [ ] 4. 输出成交记录（trade id / 价格 / 数量 / 双边 order id）
- [ ] 5. 补测试：价格相等、数量不整除、重复 id、撤单后再挂、大量订单
- [ ] 6. 加 benchmark：插入 / 撤单 / 撮合的延迟分布（p50 / p99）
